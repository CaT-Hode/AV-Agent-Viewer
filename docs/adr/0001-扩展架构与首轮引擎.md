# ADR 0001：扩展架构与首轮引擎

日期：2026-10-09。状态：采用，范围为首轮基础实现；完整需求仍保持原基线。

## 决策

采用 Electron + React + TypeScript，以 `ViewerCore` 保存统一文档、视图、快照和事务状态。HTTP、stdio MCP、CLI 和 preload 进入同一 dispatch。组件通过能力查询开放操作，不因同属 Office/PDF 就假定支持全部改写。

原生网页使用隔离的 WebContentsView，工作台和远程页不共享 preload/Node 能力。鼠标/键盘使用 Chromium 原生输入，截图与定位使用同一导航身份。网页读取和 HTML 预览复用可见文字采集脚本，鼠标坐标声明为 CSS 像素。参考 [Electron WebContentsView](https://www.electronjs.org/docs/latest/api/web-contents-view) 和 [webContents 输入/截图 API](https://www.electronjs.org/docs/latest/api/web-contents)。

首轮 Office 使用 OOXML/ExcelJS 基础适配器证明“界面编辑 → 统一修订 → 保存 → 重开”。它们不替代完整 Office 编辑引擎。ONLYOFFICE 仍是需求主选，需要先证明真实视口、选区、未保存模型、多人/多视图会话与保存回调，再接入 `OfficeGateway` 和 `ViewBridge`。开发环境未具备该服务，未安装或冒充已集成。

PDF.js 负责实际画布和文字层；pdf-lib 负责持久增补和页面操作。矩形覆盖高亮不能当成原生批注或脱敏，原有正文不做任意重写。旋转/CropBox 坐标适配未完成时显式拒绝相关增补，避免落点错位。参考 [pdf-lib 限制](https://github.com/Hopding/pdf-lib#limitations)。

HTML 首轮使用 CodeMirror 保留源码，预览经 DOMPurify 清理后置于 opaque sandbox iframe；只有本项目的遥测脚本运行。完整结构编辑、资源归档与转换留待 Tiptap/ProseMirror。保存的源码仍保留脚本和原始属性，不能把“净化预览”解释为“输出文件已经净化”。

恢复存储首轮为可替换的 JSON repository，文件写入采用临时文件替换。它用于局部状态与恢复链路验证；大文件、二进制版本、索引、审计与快照持久化后续迁移 SQLite + artifact store。当前不宣称 SQLite/FTS5 已接入。

Codex 集成提供独立 stdio MCP 与本地 app-server driver 两条路径。插件包含 manifest、发现启动器和 Skills，不依赖 hooks。app-server 使用固定问题快照和既有登录配置，创建独立线程；附着 Codex 桌面当前会话未开放。参考 [app-server 文档](https://learn.chatgpt.com/docs/app-server) 与 [插件结构](https://developers.openai.com/plugins/build/plugins)。

## 影响与升级条件

首轮能运行并验证所有现代必选类别的基础编辑，但不满足完整 P0。旧 Office 转换、完整 Office 对象、PDF 原生批注/表单、跨 frame、离线网页资源、权限绑定和包装发布各自建立验收，不降低需求基线。

替换格式引擎时保留 documentId、viewId、内容修订、准备/提交与保存语义。Live editor 需要 engineEpoch 和明确的状态桥；引擎重启/重连不能沿用旧对象定位器。新能力经过实际文件往返和 UI 位置验证后才能对外声明。

新增浏览器语义控制复用 navigationId 与视口，不使用跨页面通用 element index。新增 harness 复用 snapshot、stream、cancel，并明确会话附着与授权交互能力。JSON 迁移 SQLite 时保留旧恢复点，迁移失败不覆盖旧数据。

不在本轮自动安装完整 Office 服务、修改用户 Codex 配置、使用远程站点发布/表单作为测试或打包发布安装器。首轮测试使用本机临时样本和本地交互网页。
