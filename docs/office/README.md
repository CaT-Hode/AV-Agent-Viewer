# 内嵌 Office

Windows 通过 LibreOfficeKit 加载内置 Writer、Calc、Impress，绘制真实图块并传递鼠标、键盘和输入法。每份文档只有一个原生写入会话，各视图绑定独立 controller。

## 选区与输入

InputState 区分组合输入、在途事件、普通文字/单元格编辑和模态状态；“文字编辑中”不能一律禁用属性查询。Word/PPT 区分对象选中与对象内部文字范围，使用原生容器及范围身份，不能搜索相同文字猜目标。

PPT Outliner 撤销后可把范围收为光标，仍处于文字编辑模式，此时 selection.kind 为 none；不能把返回的 marked shapes 冒充整段文字已选中。重新选中文字后才应用范围格式。

原子 `inspect` 在一次原生操作中取得状态、属性及命令能力。混合格式保留 mixed，粗体、斜体、下划线、删除线等按单字段明确赋值，再读回同一范围。不可安全执行的字段显示 unavailable 和原因。过期读取刷新，已派发的写操作不自动重放；连续输入按提交边界应用。

悬浮栏和手动打开面板复用同一选区租约的轻量 SelectionContext 及投影矩形，完整快照只在正文、保存、导出或检查点需要时取得。PPT 文字使用原生独立历史，格式化不能通过切换页面粗暴结束编辑。

## 完成与恢复

人工命令可选择 applied 完成级别；durability.pending 表示恢复镜像仍落后。后台检查点成功后才是 recoverable，源文件保存是另一状态。公开 SDK 默认保留持久化屏障。

显式保存、冻结和撤销仍核对引擎/选区版本。独立导出创建新文件；失败时保留原生会话和诊断，先读回实际结果。不能用旧 OOXML 镜像覆盖活跃原生模型。

## 调度与启动

Kit 在顺序屏障之间优先处理交互，合并重复可替代读取；已经开始的原生调用不被中途抢占。可视图块保持有界缓存及二进制传输。进程可在桌面启动后预热；统计区分启动等待、原生加载和请求耗时，不能把单段计时视作可编辑总时间。

尺寸、页数和页面通知只标记待核对，在安全边界比较真实几何及最终页码；重复通知或临时翻页不应让坐标、图块和缩略图反复失效。Word 正文及启动预览为顶部导航预留实际编辑空间。

当前空闲预热只启动 Kit、hook 和 UNO 通用服务；seed 只复用无文档注册，未做按格式空文档或首瓦片预热。Core 的 `adapter.open` 在打开视图前解析 OOXML 辅助模型，移到 Worker 或按需加载可减少大文件的 JS 阻塞，但不能据此解释本轮引擎已 ready 后的 5.8 秒 open 请求。原生可见文字的语义几何投影已在真实呈现后异步启用。

下一步先分别 trace 排队、临时文件写入、`documentLoadWithOptions`、`initializeForRendering`、返回状态、布局、瓦片、解码和呈现，再评估空闲时按格式最小文档预热。字体发现、导入过滤器和首次排版各占多少，现有计时尚不能证明；预热不能抢占正在进行的输入。

## 协议与单位

Kit v2 认证后同 socket 发送 framed 回复/事件，像素是二进制附件，请求仍为 JSONL。头长 24 字节，magic 为 `AVKIT02\0`；半帧、未知身份和断连清理等待，不自动降级。

像素批次上限 64 MiB；常规瓦片最多 96 个、单边 2048，窗口瓦片单边 4096。字体/线宽用 pt，样式长度 mm，形状 bounds 用 1/100mm。对话框识别控件使用 DOM，其他保留原生像素交互。

已通过真实 Windows Kit 的三格式编辑、Chromium 组合输入、PPT 范围格式及文字撤销/重做、保存重开和独立导出；1280×800 对话框通过浅/深/浅主题及 3×2 表格保存。覆盖小样本，尚不能证明系统拼音输入法、大文件或复杂母版兼容；Writer 首次打开仍出现秒级原生加载，见[性能边界](../performance/README.md)。字体和特殊控件需单独样本。[适配器](../../packages/office-runtime/native/README.md)
