# AI 阅读工具补充设计与官方参考

日期：2026-10-12。本文区分官方产品参考、本轮已交付模块与后续能力。共用工具目录、来源裁剪、右侧工具、HTTP/MCP 和模型／harness 请求已经接入同一路径。真实 Electron 中已逐个点击验证 11 项分析和 1 次选区翻译的本地服务请求；云模型输出质量和复杂格式覆盖仍未验收。最终界面和安装同步证据见[交互更新记录](UI_POLISH_2026-10-12.md)。

## 1. 阅读工具要解决的任务

阅读时最常见的需求是理解一个难句、确认一个术语、快速抓住当前内容、判断结论依据、看懂公式或表格，以及把知识转成可复习的材料。右侧应提供直接可用的任务入口，同时保留自由提问输入框。预设问答生成“材料值得问什么”，自由提问回答用户的具体问题，两者共享相同的冻结来源与运行路径。

本组工具默认生成阅读结果，不编辑原件。改写、替换、批注、翻译仍走各自的明确动作和编辑／翻译协议；选区解释不会因为模型建议而自动变成修改命令。网页内容中的指令与代码也只作为待分析材料。

## 3. 本轮工具目录

目录有 11 个工具，分为理解、分析和学习三组。每个工具具有稳定 ID、图标、名称、描述、默认范围、支持范围和任务提示。工具的默认范围是产品建议；当前组件先选择有效选区，没有有效选区时初始选“当前可见”，执行前仍要求来源有效。用户选过范围后不会因选区失效自动扩大读取。

| 分组 | ID／名称 | 建议范围 | 输出要求 | 必须保留的边界 |
|---|---|---|---|---|
| 理解 | `summary` 摘要 | 当前可见 | 一句概括＋至多 5 条主要内容与结论。 | 保留对象、条件和不确定性；当前片段不能称为全文摘要。 |
| 理解 | `explain` 解释片段 | 选区 | 原意、必要背景、推理步骤；需要时给注明的示例。 | 补充解释与原文事实分开；来源不足时说明。 |
| 理解 | `terms` 术语释义 | 选区 | 最多 8 个术语的定义、此处含义及易混点。 | 缩写歧义不能编造全称；通用定义与本文结论分开。 |
| 理解 | `key-points` 关键点 | 当前可见 | 至多 7 个主张、证据、条件、限制或未决问题。 | 数值带单位、比较基准；不能省略限制。 |
| 分析 | `evidence` 证据摘录 | 选区 | 主张与短原文摘录配对，列出已提供位置。 | 摘录须来自材料，不能虚构页码、网址或缺失证据。 |
| 分析 | `outline` 内容大纲 | 当前可见 | 至多三级结构，说明问题、方法、结果、限制的关系。 | 推导结构注明“归纳结构”，不添加未读章节。 |
| 分析 | `argument-review` 论点审查 | 选区 | 主张、证据、假设、推理链和可能缺口。 | 这是材料内的批判性阅读，不宣称已经核实外部事实。 |
| 分析 | `formula` 公式解释 | 选区 | 符号、参数、单位、依赖、步骤与成立条件。 | 无公式或定义时拒绝猜测；解释不等于计算引擎，不自动修改或重算。 |
| 分析 | `table` 表格分析 | 当前可见 | 字段、单位、覆盖范围；可见趋势、异常、缺失与可比条件。 | 局部行不能当全表统计；不补缺失数据，不猜真实单元格类型。 |
| 学习 | `reading-questions` 阅读问答 | 当前可见 | 3～5 个关键问题、来源内答案及依据。 | 无法回答的明确标记，不补材料外结论。 |
| 学习 | `flashcards` 学习卡片 | 选区 | 至多 6 张问题、简短答案、来源依据。 | 优先概念、条件、因果和比较；本轮结果是文本卡片，尚无复习排程。 |

公式和表格工具不只用于 Excel。Markdown、PDF、网页或 Word 中的公式／表格也可以提供来源；是否有可读结构取决于实际提取结果，不能仅靠文件扩展名宣称具有分析输入。PPT 的可见内容通常只覆盖当前幻灯片和可读对象，不等于整套演示文稿。

## 4. 来源范围与冻结规则

### 4.1 两个默认范围

- **选中内容**：只发送冻结快照的有效选区。没有选区、选区只有空白或当前阅读状态未就绪时拒绝执行，不改用当前页。
- **当前可见**：只发送发起时冻结的 `visibleText`。如果已有选区，裁剪后的输入会清空该选区，避免原有 provider 的“优先选区”逻辑读取错误范围。

前端显示当前范围、字符数和固定来源状态，不重复堆放正文。工具运行时禁用重复发起，错误保留在工具组内，由现有任务路径处理模型配置、取消和失败。选择不同工具不会偷偷更改范围。

### 4.2 不是只在提示中限制

`scopedReadingSnapshot(snapshot, scope)` 在共享包内生成新的 provider-facing 数据包：

| 保留／生成 | 清除 |
|---|---|
| 快照 ID、schemaVersion、创建时间；文档 ID、标题、格式、内容版本、磁盘版本、未保存标记；view 身份、阅读版本、时间、质量与 actor；位置和视口元数据。 | 原文件路径、原全文模型、块／幻灯片／表格集合、原文警告、其他范围的文字；位置中的 `quote` 也清除，避免带出比选区更长的段落。 |
| `sourceScope`、`sourceText`；兼容 `document.model` 仅为 `{format, text: sourceText}`；当前范围对应的 context 文本。 | 所有未知新增 document/context 字段不通过 spread 转发，防止未来正文附件意外扩大输入。 |

原快照与未保存模型不被改变；返回的 locator、viewport、矩形等可变元数据也不与输入共用引用。内容版本或文档身份不一致时拒绝。范围内的 sourceText 是只读阅读数据；裁剪模型的 capabilities 不提供文件编辑与保存能力。

这个数据包仍保留原快照身份，便于结果关联本次来源，但不能用于覆盖快照库中的完整编辑快照。主线应只将裁剪副本交给执行阅读任务的 driver；准备编辑、翻译文件、保存等继续使用各自正式接口。

### 4.3 全文暂不开放

组件 `allowDocumentScope` 默认 `false`，共享裁剪 helper 当前无条件拒绝 `document`。未来全文能力需要专门提取接口，明确页数、章节／单元格范围、OCR／未处理对象、实际截断和 token 预算，再允许用户主动选择。仅发现 model 有 text 不足以证明完整提取。

尤其 Excel 的当前模型可能限于导入行列视图；PDF 文本层、扫描页和复杂图表也可能不完整。运行方不能把“已有 model”直接等同于全部内容。已有 provider 对过长输入的限制需要报告截断范围，不能悄悄截取后继续称作完整选区／完整可见内容。

## 5. 实现与统一 harness 路径

| 模块 | 职责 |
|---|---|
| `packages/ai-reading-tools/src/index.ts` | UI 与 harness 共用的可序列化目录、ID、标签、固定提示、范围可用性、实际来源裁剪；不依赖 renderer，不调用网络。 |
| `apps/desktop/src/renderer/lib/ai-reading-tools.ts` | 只 re-export 共用包，避免 UI 与外部工具各维护一套名称或提示。 |
| `apps/desktop/src/renderer/components/AIReadingTools.tsx` | 显式范围切换、三组图标工具、busy 与错误状态；通过 `onRun(tool, scope)` 把任务交给 App。 |
| 现有 App／core／provider／MCP 路由 | 冻结目标、选模型、裁剪输入、提交任务、流式／非流式结果、取消、状态和对外调用；本组不再创建第二个请求系统。 |

组件接口：`context?`、`snapshot?`、`format?`、`busy?`、`allowDocumentScope?`、`onRun(tool, scope)`。已有固定快照优先于 live context，避免用户切换页后工具入口与来源发生漂移。工具 ID 从共用目录校验，不能通过客户端传来的任意 prompt 字段替换内置任务说明。

对外接口支持查询目录和执行目录动作。执行参数包含 `toolId`、明确 `scope`，以及现有 `viewId`／`snapshotId` 定位；返回现有任务 ID 和冻结快照身份。HTTP、MCP、UI 复用同一 action，不分别拼提示与裁剪规则。调用方不能通过省略 scope 得到更大的默认范围；未知工具、未知范围、空内容和快照目标错配均拒绝。幂等缓存为当前进程内最多 256 项；在途记录不淘汰，已结束记录可能被新请求淘汰。重启或记录淘汰后，应先查询原任务，不承诺持久同键复用。

本轮的“证据摘录”提示要求短引用，但模型返回的自然语言本身不是机器已验证引用。完整证据功能需进一步结构化 `quote + locator + sourceRevision`，校验 quote 是否逐字存在、定位是否仍有效，再展示可点击回跳。未完成这种验证时，不能将模型自行生成的页码或链接渲染成可信来源按钮。

## 6. 延后能力和升级接口

| 后续能力 | 需要补的接口／验收 |
|---|---|
| 全文摘要与章节导读 | 完整文本提取、分段／并发／取消、源版本冻结、coverage 与预算报告；不能用现有局部模型替代。 |
| 结构化证据引用与回跳 | 来源范围内的精确 quote 校验、稳定锚点、原文变化失效提示；失效时不跳错页。 |
| 多文档比较／证据矩阵 | 用户显式选定文件集合，各文件版本及范围独立冻结；新增来源需要显式扩展，不继承整个工作区。 |
| 事实核验与相关文献 | 独立联网任务和来源列表，记录检索时间、外部证据与反例；与材料内论点审查分开。 |
| OCR、图表与公式视觉理解 | 图像范围、分辨率、提取置信度与未覆盖信息；不从损坏表格补数值。 |
| 确定性表格计算 | 真正的类型、公式与依赖接口，计算引擎及重算结果；LLM 解释不能替代计算或全表统计。 |
| 持久化学习卡片与测验 | 独立产物、来源关联、卡片编辑、测验反馈、复习排程与导出；清理缓存不能删除学习资料。 |
| 解释深度／回答风格 | 模型 profile／任务参数中的入门、专业、简短、详细；运行中的请求固定发起配置。 |
| 音频、视频、思维导图 | 单独生成任务、耗时／预算、格式产物与可恢复状态；无需在本轮新增服务依赖。 |

## 7. 验收与当前证据

纯目录／来源测试 **9/9**，SDK／MCP 共用动作测试 **7/7**，真实子进程 Codex 协议测试 **3/3** 通过。测试覆盖目录唯一性、两种范围隔离、全文／路径／未来字段移除、空选区不回退、版本与目标拒绝、冻结来源、幂等请求和范围受限 Codex 输入。局部阅读任务不会注入 AgentViewer 的全文 MCP 桥或提示模型扩大范围；独立 harness 会话保留原有桥接。

`ai-reading-ui.e2e.ts` 在冻结构建 `index-BLqvx-4v / index-BrjwlpP0` 上通过。证据目录为 `C:/Users/cth/AppData/Local/Temp/agentviewer-ai-reading-ui-z8nOEr/evidence`：11 个动作和选区翻译实际调用本地兼容服务，原文模型／dirty／磁盘字节不变，结果和译文均为真实折射；复制使用隔离 renderer Clipboard stub，未改用户系统剪贴板；生成的独立 Markdown 经正常 Ctrl+S 写盘。Tooltip 与 native Tooltip 均保持磨砂，无固色回切。随后构建仅修改左栏初始化，AI 独立 native 浮窗和最终安装另行验收。

接口和界面验收继续遵循下列规则；复杂格式与外部服务验收不能由基础样本替代：

1. UI、HTTP 和 MCP 得到相同工具目录、提示与 sourceScope；visible 执行不被旧选区抢走。
2. 连续选区、翻页、切标签后，已发任务保留原来源；旧结果不能冒充新来源。
3. 阅读任务前后，原文件字节、dirty 状态、编辑撤销栈保持一致。
4. 无模型、连接失败、取消、输入超限有可读状态，不反复打开设置窗口。
5. PDF 扫描页、公式缺定义、表格残缺、局部 Excel 范围均明确能力与覆盖限制。
6. 结果的原始模型文字不执行 HTML／脚本，不直接调用编辑操作；引用经过验证后才提供可信跳转。
