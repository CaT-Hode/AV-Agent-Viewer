# 内嵌 Office 核心与共享阅读画布

这一轮将 Writer、Calc、Impress 的文档模型、排版和计算留在同一份 LibreOffice 核心中，将文档呈现、输入、左侧工具、选区浮窗和 Agent 提示交给 AgentViewer。主线使用 LibreOfficeKit DLL；每份文件不再启动一个 Office 程序或嵌入一个 Office 窗口。旧 HWND host 保留其代码与协议用于兼容研究，桌面阅读页默认使用 tiled surface。

## 引擎边界

- Windows x64，内置 LibreOffice 26.8.1.1，BuildId `bf6ef2662401c7d6dce671ab4deb26ee0af3a7c1`。
- 每个应用运行时按需建立一个核心工作进程，每个文档只有一个可写模型；多个视图使用该模型的控制器。
- 不启动 `soffice.exe`、`soffice.com` 或 `soffice.bin` 作为编辑界面。工作进程直接加载已有核心 DLL，通过自己的 UI 线程执行 C API 和 UNO 对象操作。
- 图块、鼠标、键盘、中文组合输入、选择、窗口绘制使用固定版本的 [LibreOfficeKit API](https://github.com/LibreOffice/core/blob/libreoffice-26.8.1.1/include/LibreOfficeKit/LibreOfficeKit.h)。类型化文档修改继续复用现有 UNO 模型事务和唯一写入会话。
- Windows 光栅适配器只作用于自有工作进程，在初始化前核验 DLL 哈希、导出、RVA 和指令；不修改发行引擎文件。实现与后续源码构建方案见 `packages/office-runtime/native/README.md`。
- 工作进程没有宿主 CLI 参数，私有 TCP 仅用于接收受限 JSONL 请求；输出仍通过标准输出的明确刷新交付。私有短路径 profile 与文档恢复目录分开，避免 Windows 启动路径问题。

## 呈现、输入与状态

`OfficeSurfaceState` 将文档坐标固定为 twips，屏幕视口固定为 CSS 像素，DPR 只增加像素密度。`documentOriginCss` 显式记录居中纸面与滚动后的原点，人与 MCP 的操作都据此转换；不能用裁剪后的可见文档原点代替。

正文使用有限图块缓存。局部损伤只淘汰相交的图块，包括未返回的旧绘制；换页、缩放、DPR 或整面失效才创建新的完整绘制代次。过期图块可以重新定位后绘制，未确认的修改请求不自动重放。

键盘与指针在独立输入流中按连续序号确认。中文组合输入保留预编辑与一次提交。明确的人类保存动作可以提交当前单元格或演示文字编辑；普通读取、后台镜像和 Agent 的检查不能偷偷提交用户输入。

同一视图的布局提交与人类输入共用串行调度，在输入发送前确认实际坐标版本；焦点和滚动观察器不能在两者之间插入新布局。会话替换、外部修改或未知回执仍会使操作失效，不自动重放编辑。Calc 跳转到已用区域以外的合法单元格时，只扩展该工作表视图的滚动范围，不写入空白单元格或改变文件的已用区域。

原生输入回执前，在受控 UI 线程调用同版本 DLL 的公开 `Application::Reschedule(true)`，处理实际事件及其派生队列，并排除 RPC 重入。显式保存只提交一次当前编辑，再等待真实编辑结束通知；事件队列或通知在限定时间内未稳定时明确报错，不能用固定等待时间或清空标志假定完成。正文输入携带冻结的页／工作表身份，worker 在任何修改前再次核验；窗口输入使用独立窗口身份。

选区浮窗复用导航玻璃，通过真实引擎选区和几何生成。它不提交伪造的 DOM `report-context`，每个结果绑定会话、引擎版本和选区身份；滚动只更新几何，取消和替换选区会使旧浮窗失效。Agent 光标、目标提示和标签控制状态仍绑定具体视图。

## 左栏与 Harness

Word、PPT、Excel 继续使用各自的左侧分类与实际命令目录。常用属性用应用控件，复杂功能通过引擎命令及实际窗口呈现。主进程的 private surface IPC 管理图块、输入和窗口，不作为对外任意地址/路径执行接口。

常用操作使用 32×32 的语义图标按钮，悬停时显示操作名称和不可用原因，读屏名称与原命令标识保留。字体、字号、数值和属性输入保留文字；高级命令搜索保留可检索的名称和 UNO 标识。图标不创建独立的正文采样层。

Harness 继续使用已有 `office_status`、`office_query`、`office_execute`、`office_input`、`office_capture`、`office_navigate` 及选择工具接口。HTTP、MCP 与 UI 访问同一个编辑源，保留版本校验、条件撤销、快照和保存回执。

Community LibreOfficeKit 使用 WINDOW 回调与窗口绘制，不假定存在 Collabora 的 JSDIALOG API。独立窗口剪贴板在没有可靠 API 时报告不可用，不能用正文选择或文档视图剪贴板冒充。窗口的原生模态属性未知时不伪造该属性。

阅读位置取自同一模型的实际布局投影，来源标为 `actual-model-projection`，与旧 `actual-a11y` 区分。无法确认几何的区域必须报告未准备或截断，不把全文填入“当前可见文字”。

## 画布、纸面与导航

外围画布有炫彩、海湾、鸢尾、香槟和月光五组配色，支持深浅主题及 120 秒缓慢漂移。减少/关闭动效时静止。纸面独立设置，默认白色；文件中明确的页面、单元格填色或图片保持自己的颜色。阅读偏好不进入普通文档保存或打印。

正文可用区域始终避开两侧细栏，避免正文、滚动条或输入目标被遮挡。导航只在两个展开侧栏之间的安全区域呈现，按可用宽度收紧间距、缩短标题并收纳次要操作。PPT 额外将幻灯片放在展开栏之间的安全视口，默认按真实引擎缩放适应页面；侧栏改变宽度或窗口改变大小后重新适应。用户通过导航比例、Ctrl+滚轮或 harness 调整比例后保留手动缩放，不再强制适应。Word、Calc、PDF 的侧栏展开继续保留已有正文画布和滚动位置。

左右栏共用可打断的解析弹簧，切换方向保留当前位置和速度，静止后才卸载收起的面板。标准档响应为 0.4 秒、阻尼比 0.76；优雅档为 0.58 秒、阻尼比 0.68。展开／收起运动只作用于侧栏呈现层；PPT 的安全视口与自动适应另行同步，其他正文画布保持不变。透明度与物理过冲分开，减少动效与关闭档采用既有无障碍策略；网页独立视图中的右栏使用同一运动状态。

展开面板的高度取自单一工具树的自然内容、标题与边距，最大为工作区高度减 22px。少量内容不占满窗口，长工具箱在面板内部滚动。栏目切换、异步内容增加和窗口大小变化共用高度弹簧，重定向时保留实时高度与速度；不复制一份隐藏编辑器测量。标准档高度响应为 0.38 秒、阻尼比 0.84；优雅档为 0.56 秒、阻尼比 0.76。网页独立浮层与主窗口中的锚框使用同一实时高度，逐帧更新不触发整页 React 渲染。减少／关闭动效时直接调整高度。

## 验证边界

底层 gate 已验证三个实际格式的同模型绘制、真实命令目录、同格式快照与正常关闭。桌面验收另行覆盖中文组合输入、左栏属性、选择浮窗、MCP 坐标、保存重开、真实窗口、多开和纸面颜色；底层成功不代替桌面验收。

共享侧栏与导航已在真实 Electron 中通过 100%、150%、200% 缩放验收。`tests/sidebar-presence.e2e.ts` 检查两档左右栏的真实过冲、反向切换、静止后卸载、无障碍档以及网页独立浮层；正文边界和导航避让逐帧校验。`tests/frosted-shadow.e2e.ts` 覆盖深浅主题中的侧栏、提示、弹窗与设置，关闭外投影的像素对照确认侧栏内部没有自身阴影回采。

当前 staged EXE 的桌面验收另外通过短／长侧栏高度、栏目切换与反向动画、网页原生浮层同步，以及 PPT 的适应页面、手动缩放保留、MCP 滚动后截图和点击坐标。`tests/embedded-office.e2e.ts` 在临时文件与独立配置中完成 Word、Calc、Impress 的真实输入、中文组合输入、左侧工具、保存和新模型重开；同时验证原生 InsertTable 窗口的绘制、键盘输入和取消。该验收不等于所有 LibreOffice 命令和复杂文件均已覆盖。

PPT 的非空原生文字选择使用实际 UNO 光标范围。活动文字编辑中的文档级 Undo/Redo 明确拒绝；完成输入后，通过同模型撤销管理器确认真实历史变化。缺少修改通知时才补版本，已有通知不重复计数，过期选区不能用于修改。独立底层 gate 已验证局部文字与样式、后缀保持、多视图、Undo/Redo 和稳定快照；`tests/native-office-kit-history.test.ts` 保留对应回归。

LibreOffice 的 OOXML 导出具有自己的互操作行为，尤其字体度量造成的 Excel 列宽换算。必须与未经编辑的同引擎导出基线比较，不能承诺所有文件的像素或字节完全相同。

## 启动与日志管道

主进程在 Electron 与服务导入之前安装标准输出／错误管道保护。启动器关闭日志管道后，实际 `EPIPE` 只停用断开的日志通道；另一通道与应用控制继续工作。其他 I/O 错误仍抛出，不使用全局 `uncaughtException` 处理器隐藏异常。`tests/safe-stdio.test.ts` 通过真实操作系统管道断开和存活控制请求验证这一行为，并确认非 `EPIPE` 错误仍导致可见失败。
