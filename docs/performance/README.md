# 性能实现与证据

## 当前处理

Word 可见正文先由原生页游标取页面范围，只测量该范围段落；跨页表格保留单元格和行边界，巨段裁切首尾。缓存绑定内容版本、页面几何与页区间，探测不改变人工选择和撤销。旧实现每次修改后重新测量全文前2000段，会阻塞状态读取与输入回执，且遗漏后部页面。

Office 原生范围操作采用局部读回；服务层仍需恢复检查点，磁盘保存独立。交互优先、合并读取、分阶段空闲预热；已经开始的 LibreOffice 调用不能抢占。首帧不再退到2500ms心跳。

Markdown 采用范围输入、有界解析与可视装饰。点击不先移动选区或展开整行语法；拖选过程中保持字形位置，块组件纳入 CodeMirror 高度测量。浮栏按所有者识别提示框，仅在碰撞几何改变时更新弹簧目标。

## 10月22日 Kit 采样

真实原生引擎 API；Word 为3000段文档，PPT为内置故事样本。每格式10次独立进程/私有profile打开、10次同进程打开、100次顺序文字修改。下表单位ms，均为P50/P95。

| 格式 | 新进程打开 | 同进程打开 | 修改及真实读回 |
| --- | --- | --- | --- |
| Word | 4104/5787 | 741/1266 | 42/67 |
| PPT | 4106/4923 | 217/930 | 76/110 |

打开计时包含引擎就绪和导入，后续首次正文投影另计：Word新/同进程P95为264/179ms，PPT为15/14ms。200次修改均 applied/verified。snapshot加独立写盘各仅1次：Word219ms、PPT1499ms，不能作为保存P95。

这些是 Kit API 时延，不含 Electron 呈现、恢复检查点和 HTTP 调度，不能推导键盘到屏幕延迟。OS文件缓存未控制，新进程不等于磁盘冷态。冷启动仍有约4–6秒引擎开销，未达到瞬时打开。原始样本保存在本轮 TEMP/agentviewer-office-speed-20261022/final-benchmark/result.json，包含逐项耗时及源码SHA；不与10月19日不同工作量的服务分布计算加速比。

## 回归与边界

现有50项预算内补充多缩放/来源位置双断言、跨格式正反拖选、巨段编辑与历史；Word覆盖超过2000段、超过2000格、11万字符单段的后部页面，检查选择、dirty与Undo不变。Electron模拟输入不代表系统输入法或物理输入验收。

巨段双解析、原生导入和恢复持久化仍需分别采样。短交互每组至少100次，打开至少10次，报告排队、执行、读回、持久化和呈现；JS heap不等于总内存。MCP参考预算和宿主认证分别报告。
