# 性能实现与证据

## 处理路径

Office 私有配置准备与 DLL 加载并行；独立的注册目录与 UI 资源校验也并行，原生 hook 前全部汇合。快照逐视图检查真实输入标志，避免重复生成选区和全文投影；服务层复用本次串行事务已验证的摘要。保存仍读盘校验并原子发布。

恢复使用至多两个读取器；大 blob 和 delta 链仍串行，避免挤满后台校验队列。Core 接管恢复字节时保留身份，首次检查点复用已验证 blob。损坏来源使整次恢复失败，不发布部分工作区。

Word 按实际页面限制段落测量，缓存绑定内容和页几何。Markdown 按范围输入和可视区生成装饰，鼠标按住期间冻结语法显示，松开后局部展开当前格式符号。悬浮层共享布局读阶段，通知不反向触发全量测量，静止位姿不重复写样式，运动复用玻璃纹理。网页语义操作只确保页面已加载，不先重复提取正文。

## 10月22日采样

Kit API 同负载前后各采样：每格式10次独立进程打开、10次同进程打开、100次文字修改及真实读回，另各10次变化快照、复用快照和独立写盘确认。单位ms，以下为前→后P95。

| 格式 | 新进程打开 | 修改及读回 | 变化快照 |
| --- | --- | --- | --- |
| Word，3000段 | 5143→5004 | 86→67 | 179→149 |
| Excel，内置样本 | 4854→4414 | 16→16 | 416→453 |
| PPT，内置样本 | 3909→4071 | 74→91 | 1251→1416 |

第二轮每格式前后各10次新进程打开，冻结相同输入并交替执行。P50/P95：Word 3681/4004→3289/3883，Excel 2955/3944→2894/3384，PPT 2954/3943→2800/3179。资源准备与注册校验重叠，hook开始P50分别提前75、103、137ms；首次文字投影持平。两侧共享worker的快照函数有差异，此轮未调用，不将总体变化归因为单一改动。

PPT改用原生XStorage中介和无视图只读模型。两轮各前后10次变化快照、每份独立Kit重开；第二轮反转版本顺序。整体P50为832→750、760→724ms，序列化128→84、118→83ms；clone导入525→468、468→457ms，仍是主成本。反序P95为921→900ms，不能由小样本宣称长尾已解决。纯内存流及单独去控制器未有稳定收益，未采用。XStorage底层可用临时文件，不称纯内存保存。

12份混合Office恢复，10次采样：恢复P50为67.9→31.6ms，P95为84.4→80.8ms；首检查点P50为7.6→3.8ms、P95为10.4→11.4ms，不再重复冻结2.63MB来源。100次后续元数据检查点P95为5.7→4.2ms。

公共浮层真实Chromium探针：20父层和20嵌套提示，100次移动的DOMRect读取8880→3960；100次已测量边界通知的额外读取6060→0。这是观察器工作量，不是屏幕延迟。

10月28日Electron对照：普通、玻璃前景和AI浮窗分别前后各100次；组件提交到首次可见样式P50由53.0–53.1降至39.7ms，P95由53.4–53.5降至39.9–40.3ms。双RAF改单RAF，动画时长不变；去掉额外CSS起始规则仍保留渐变，因此未采用。启动级联延后取消，导航在首个测量帧推进原弹簧。证据在`animation-response`，不代表物理输入到屏幕。

## 验证边界

历史采样在`artifacts/verification/office-cold-performance`、`recovery-performance`、`hover-performance`和`mcp-web-final`。当前验收先构建，以buildId关联证据，不再全量扫描SHA；旧完整回归已退役。OS缓存及同机负载未控制，新进程不代表冷盘；Kit数据不含Electron呈现、键盘到屏幕延迟或Codex桌面MCP认证。
