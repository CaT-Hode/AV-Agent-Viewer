# 性能实现与证据

## 处理路径

Office 私有配置、注册和资源校验与 DLL 加载并行，原生 hook 前汇合。快照逐视图检查真实输入标志，避免为检查输入重复生成选区和全文投影；服务层复用本次串行事务已验证的摘要。PPT 保留隔离只读 ODP 导出及颜色、撤销检查，保存仍读盘校验并原子发布。

恢复使用至多两个读取器；大 blob 和 delta 链仍串行，避免挤满后台校验队列。Core 接管恢复字节时保留身份，首次检查点复用已验证 blob。损坏来源使整次恢复失败，不发布部分工作区。

Word 按实际页面限制段落测量，缓存绑定内容和页几何。Markdown 按范围输入和可视区生成装饰，点击、拖选不展开隐藏语法造成字形跳动。悬浮层共享布局读阶段，通知不反向触发全量测量，静止位姿不重复写样式，运动复用玻璃纹理。网页语义操作只确保页面已加载，不先重复提取正文。

## 10月22日采样

Kit API 同负载前后各采样：每格式10次独立进程打开、10次同进程打开、100次文字修改及真实读回，另各10次变化快照、复用快照和独立写盘确认。单位ms，以下为前→后P95。

| 格式 | 新进程打开 | 修改及读回 | 变化快照 |
| --- | --- | --- | --- |
| Word，3000段 | 5143→5004 | 86→67 | 179→149 |
| Excel，内置样本 | 4854→4414 | 16→16 | 416→453 |
| PPT，内置样本 | 3909→4071 | 74→91 | 1251→1416 |

PPT最终另优化临时ODP文件同步，独立各10次快照P95为949→1055ms，未证实总耗时提速，clone导入仍是主成本。结果混合，不能宣称每格式均提速。OS缓存和同机负载未控制，新进程不是磁盘冷态；Word XML负载相同，ZIP时间不同。Kit数据不包含服务恢复、Electron呈现或键盘到屏幕延迟。

12份混合Office恢复，10次采样：恢复P50为67.9→31.6ms，P95为84.4→80.8ms；首检查点P50为7.6→3.8ms、P95为10.4→11.4ms，不再重复冻结2.63MB来源。100次后续元数据检查点P95为5.7→4.2ms。

公共浮层真实Chromium探针：20父层和20嵌套提示，100次移动的DOMRect读取8880→3960；100次已测量边界通知的额外读取6060→0。这是观察器工作量，不是屏幕延迟。
