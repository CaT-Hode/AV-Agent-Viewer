日期：2026-10-13。环境：Windows 已安装的 AgentViewer，独立临时 profile，实际可见 Electron 窗口。

## 调用方式

这轮先以 Markdown 列大纲，再用 Excel 整理事件与记忆代价，随后完成 Word 五章小说、八页 PPT 和独立 HTML 展示。创作内容使用真实 MCP 的读取、准备补丁、应用补丁、保存接口写入阅读器；交互式客户端逐项调用并观察结果，不以生成脚本测试替代实际操作。Playwright/CDP 仅承担只读界面观察与截图。写作构思、格式排查并行，Excel 的 MCP 编排与主线 Word/PPT 创作并行。

起初 MCP 缺少新建工具，使用空白文本及原有 Office 样本启动，随后通过格式命令清除示例并写入原创内容；此次修复后，已实际验证空白 Word/PPT/Excel/PDF/HTML 及本记录 Markdown 的新建、写入与保存。重复同一新建键返回同一视图。

## 实际发现与修复

| 问题 | 原因与处理 |
| --- | --- |
| MCP 无空白文档创建入口 | 新增 document_create，按格式真正创建空白内容，校验标题与扩展名；同一实例内幂等复用，不在创建时写磁盘。 |
| MCP 不能跳到 Office 目标 | 新增 reader_navigate，支持段落、幻灯片、工作表/单元格，校验源版本；返回 requested 后再读取真实 UI 上下文确认。 |
| PPT、Excel 无内容搜索，HTML 无可用目录 | 从格式模型提取可搜索单元及位置；HTML 用 parse5 排除样式和脚本，并提取正文标题。 |
| Excel 标题样式污染正文 | ExcelJS 加载后共享 cell.style；格式修改前深复制目标样式，再逐表重新设置标题、表头和正文。 |
| Word 引用标题样式但未定义 styles.xml | 显式应用/插入段落时补齐缺少的内置样式、关系与内容类型，保留已有用户样式。 |

| 后续问题 | 原因与处理 |
| --- | --- |
| PPT 缩略图黑字与布局失真 | 改为按 EMU 坐标投影实际对象，保留颜色、大小、背景、旋转及换行。 |
| Word 显示 PPT 特有限制 | 将 Word 和 PPT 引擎限制提示分别定义。 |
| HTML 装饰图造成水平溢出 | 在阅读器通过 MCP 修改 hero 的裁剪及 SVG 定位；重读实际 DOM 后，scrollWidth 与 clientWidth 均为1019。 |
| 安装版 MCP 启动找不到 pptxgenjs | 导出 schema 意外加载了文档引擎开发依赖；把新建/导航 schema 分到只依赖 Zod 的模块，安装版 stdio 实际重连成功。 |

另经审查补充：冻结窗格导航应扣除真实 sticky 行列遮挡；HTML 的 div/body 裸文字也应纳入搜索而不重复提取祖孙内容。最终安装版已实际验证：冻结3行2列后 G15→D4 的定位回跳避开固定区域；div 正文搜索返回唯一匹配与 HTML 块位置。

补充 UI 回归实际复现 Excel 单击后的选区胶囊缺失：React 发布新选区后，同一 pointerdown 的 document 冒泡关闭又取消异步请求。关闭监听改为捕获阶段，先清旧选区再接收新选区。等待实际单元格内容后，单击显示、斜体修改、外部点击关闭三项均通过；没有用拖选绕过缺陷。

## 能力边界与后续建议

Excel 基础引擎保留公式但不计算结果，需完整计算引擎重算；当前公式格为空缓存不是“十二户=空”。Office 本地预览为对象/段落模型，不能宣称与 LibreOffice 的分页、样式继承、母版、复杂图表或修订完全等价。MCP 新建幂等缓存限当前 core 的256个完成项，不跨重启持久化；导航回执 requested 不能代替读取实际上下文。

后续增强应采用能力发现驱动工具栏，给完整 Office 引擎、公式计算、分页渲染等保留独立适配器。AI 自动翻译、OCR、外部模型和云端服务不在本轮验收范围。

调用日志、截图、独立导出PDF及临时创建验证文件保存在系统临时目录，未提交包含连接信息的 profile；正式五种作品和本记录进入仓库。运行实例始终通过正常关闭更新，未强制终止用户进程。

## 目录与阅读范围最终补修

HTML后端已有目录，但前端仍从通用blocks读取而显示空目录。现统一界面与MCP的标题身份，新增html-heading导航；可信iframe桥接按视图、文档、版本和请求身份校验，展开目标details后等待真实布局再确认。不可见目标不会写入agent成功状态。Word目录采用实际段落索引，PPT与Excel分别定位幻灯片和工作表，避免混用标题序号或表达式优先级导致错误格式分支。

实际跳到第五章后发现，Chrome为已折叠details的正文保留旧Range几何，导致回读混入未展开章节。已增加每次采样复用的可见性缓存，以checkVisibility及祖先状态排除未绘制、隐藏、透明和折叠内容；SVG及兼容环境保留专门退路。独立Electron基线先失败，修复后同一小说样本通过。

最终安装版再次用真实MCP定位“新的初见”：details已展开，标题位于853px视口内的413–441px；上下文为confirmed、actor=agent，选区为空。visibleText包含第五章“天亮以后”，排除第二、三、四章三处独有正文；18个界面目录与MCP目录一致。HTML仍为版本2、未修改。目录UI复验也验证Word第109段、PPT第五页、Excel第二工作表、隐藏目标失败和原文件字节不变。

最后审查发现HTML外链可能替换同一WindowProxy，使旧wildcard导航消息暴露nonce。已改为原始可信srcDoc的MessageChannel，严格校验源、nonce与单一端口；导航、正文、错误及完成确认只走私有端口。load/pagehide/卸载使旧上下文和pending失效。真实外站执行两次伪造，仅收到1条无token、无端口的握手提示，没有收到导航命令；上下文清为human/not-ready，旧目标导航实际失败。

目录回归另复现120ms节流丢末次Word滚动：DOM目标已可见但上下文停在段0。已补leading+latest trailing，延迟重新采实际几何、force取消旧等待、视图身份变化同步取消。相同UI断言通过，未靠初始化延迟绕过。最终安装版Ca1rvOIq再次实际MCP跳至第五章并回读confirmed/agent的真实正文，折叠章节仍排除。
